# 要件（AI入力用の正本）

顧客提出用の `docs/deliverables/要件定義書.docx` は、本書の内容を整形した出力物。要件を変えるときは本書を先に直す。

## 前提・制約

- 利用者は1名。認証・認可なし
- チェックできるのは当日分のみ。過去日付の編集、未来日付のチェックは不可
- 「今日」は端末のローカル日付（`YYYY-MM-DD`）。チェック操作のたびに取り直してAPIに渡す。サーバーは今日以外の日付を拒否する
- 既存のPostgreSQLを使う。開発用とテスト用でDBを分ける

## 機能要件

| ID | 機能 | 内容 |
|---|---|---|
| F-01 | 習慣の登録 | 習慣名を入力して追加。前後の空白は除去。空、および登録済みと同名は不可（画面にエラー表示） |
| F-02 | 習慣の一覧表示 | 登録済みの習慣を一覧表示。各習慣に今日のチェック状態と連続達成日数を表示 |
| F-03 | 今日のチェック | 習慣ごとに今日の実施済みを付け外し。同じ操作を繰り返しても二重に記録されない（冪等）。操作は習慣の更新として扱い、行バージョンで同時実行を制御する（N-07） |
| F-04 | 連続達成日数 | 下記「ストリーク規則」に従って表示 |
| F-05 | 習慣の削除 | 習慣と、そのチェック履歴を削除。同名で再登録した場合は新規扱い |
| F-06 | データの保持 | DBに保存され、再読み込みしても失われない |

### ストリーク規則

- 今日が実施済み → 今日から遡って連続した日数
- 今日が未実施 → 昨日から遡って連続した日数
- 実施していない日が1日でもあればそこで止める（0に戻る）
- 月またぎ・年またぎ・うるう日（2/29）を正しく数える
- 未来日付の記録は含めない
- 同じ日付の重複は1日と数える

## 画面要件

見た目は、リポジトリ直下の `DESIGN.md`（QuestUI デザインシステム）を参考にする。

1画面。習慣の追加欄（入力欄と追加ボタン、エラーは欄の近くに表示）／習慣の行（今日のチェック、習慣名、連続達成日数、削除ボタン）／習慣が無いときの案内／通信・保存失敗時のエラー表示

## データ要件

| データ | 項目 | 制約 |
|---|---|---|
| 習慣 | ID、習慣名、作成日時、行バージョン、トランザクションID | 習慣名は空不可・前後空白除去・同名重複不可 |
| チェック履歴 | 習慣ID、日付、行バージョン、トランザクションID | 日付は `YYYY-MM-DD`。`(習慣ID, 日付)` は一意。習慣の削除時に併せて削除 |

全テーブルに「行バージョン」（`row_version`）と「トランザクションID」（`txn_id`）を持たせる。値の更新はDBのトリガが行う（N-07、N-08）。

入力値の検証規則は `src/packages/schemas` に一本化し、画面とAPIで共有する。

## 非機能要件

| ID | 区分 | 内容 |
|---|---|---|
| N-01 | 利用環境 | 主要ブラウザ（Chrome／Edge／Firefox／Safari）のデスクトップ最新版 |
| N-02 | 性能 | 通常操作の結果が1秒以内に反映（習慣100件以内）※仮の値 |
| N-03 | 信頼性 | 同じチェック操作の重複送信でデータが二重にならない |
| N-04 | 保守性 | ストリーク計算・入力検証などの主要ロジックは自動テストで検証 |
| N-05 | セキュリティ | 習慣名は文字列として表示（スクリプトとして実行しない）。DBへの問い合わせは入力値を直接連結しない |
| N-06 | 設定管理 | 接続情報などの秘密情報は環境変数で与え、リポジトリに含めない |
| N-07 | 同時実行制御 | 楽観的ロック。全テーブルに `row_version` を持たせ、更新・削除のSQLは `WHERE row_version = :読んだ値` を付ける。成功時はトリガが `row_version` を+1する。0行の場合は、対象が無ければ404、バージョン不一致なら409（`VERSION_CONFLICT`）。DBMS固有の機能（シーケンス、`xmin` など）には依存しない |
| N-08 | 更新の追跡 | 全テーブルに `txn_id` を持たせ、その行を最後に更新したトランザクションを識別できるようにする。値はアプリがリクエストごとに発行するUUIDを、トランザクション内で設定し、トリガが記録する。保持するのは最後の更新だけで、履歴は対象外 |

## 受入基準

| No. | 確認内容 |
|---|---|
| A-01 | 習慣を2つ登録でき、一覧に表示される |
| A-02 | 空・空白のみ・同名の習慣は登録できず、エラーが表示される |
| A-03 | チェックで連続日数が増え、外すと元に戻る |
| A-04 | 再読み込みしても習慣とチェック状態が保持される |
| A-05 | 削除すると一覧から消え、同名で再登録すると連続日数が0から始まる |
| A-06 | ストリーク規則の自動テストがすべて成功する（月またぎ・年またぎ・うるう日・未来日付を含む） |
| A-07 | 画面を開いたまま日付が変わった後にチェックしても、新しい日付に記録される |
| A-08 | ブラウザのコンソールにエラーが出ない |
| A-09 | 同じ習慣を古いバージョンで更新・削除しようとすると409になり、データは変更されない。画面は最新の状態を再取得してメッセージを表示する |
| A-10 | 同時に行った更新でも、片方だけが成功し、もう片方は409になる（結合テストで確認） |
| A-11 | 更新された全行の `row_version` が+1され、同じトランザクションで更新された行の `txn_id` が一致する |
