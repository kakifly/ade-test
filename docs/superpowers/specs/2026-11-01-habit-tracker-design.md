# 習慣チェックアプリ 設計書

## 意図と背景

シンプルなWebアプリ「今日の習慣チェック」を作る。アプリ自体が目的ではなく、作る過程で次の4つのエンジニアリングを体験することが主目的である。

- **プロンプトエンジニアリング**: AIへの指示の書き方で結果がどう変わるかを知る
- **コンテキストエンジニアリング**: AIに渡す情報（CLAUDE.md、設計メモなど）の選び方と置き場所を知る
- **ハーネスエンジニアリング**: テスト、hook、ブラウザ確認など、AIの作業を支え検証する仕組みを知る
- **ループエンジニアリング**: 「実装→検証→修正」のサイクルを回して品質を上げる流れを知る

アプリは小さくても、状態管理・日付ロジック・画面を含むため、4つの体験の題材として適している。

## ゴール

- 習慣を登録・削除できる
- 今日の日付に対して、習慣ごとにチェックを付け外しできる
- 習慣ごとに連続達成日数（ストリーク）を表示する
- データはブラウザのlocalStorageに保存され、再読み込みしても残る
- 上記の挙動が自動テストで検証されている
- 4つのエンジニアリングそれぞれの体験が、作業の中で具体的な成果物（文書・設定・テスト・ログ）として残る

## 非ゴール

- ログイン、複数端末での同期、サーバーやDBの利用
- 通知、グラフ、統計画面、カレンダー表示
- 過去日付の編集（今日分のみチェック可能）

## アンチゴール（技術的に動いても失敗とみなすもの）

- 4つの体験がどれか欠けた状態で完成扱いにすること
- 体験のためにアプリを過剰に作り込み、シンプルさを失うこと
- テストが通るだけで、実際の画面で動作確認していないこと

## 制約

- 技術: HTML + CSS + バニラJavaScriptのみ。ビルド工程なし、フレームワークなし
- 保存: localStorageのみ
- ドキュメント、コミットメッセージ、PR本文は日本語。識別子とブランチ名は英語（ユーザーのグローバルCLAUDE.mdに従う）
- 日付は端末のローカル日付で扱う

## 仕様の要点

- **ストリーク**: 今日から遡って、チェックが連続している日数。今日が未チェックの場合は、昨日までの連続日数を表示する（今日チェックすればその日数に+1される）。1日でも空けたら0に戻る
- **データ**: 習慣ごとにID、名前、チェック済み日付（`YYYY-MM-DD`）の一覧を持つ
- **構成**: ストリーク計算などのロジックは画面から分離した関数にし、単体でテストできるようにする

## 4つの体験の組み立て（進め方）

1. **プロンプト**: 同じ機能について「曖昧な依頼」と「成功条件つきの明確な依頼」を両方試し、出力の差を記録する。結果は `docs/experience-log.md` にまとめる
2. **コンテキスト**: プロジェクトの `CLAUDE.md` に技術方針と方針ルールを書く。設計書を参照できる場所に置く。あるなしで結果がどう変わるかを記録する
3. **ハーネス**: ロジックの単体テストを用意する。編集のたびにテストを走らせるhookを設定する。Playwrightで実際の画面操作を確認する
4. **ループ**: ストリーク計算を最初は意図的に不完全（例: 日またぎや月またぎを考慮しない）に実装し、テスト失敗→修正→再実行のループで直す。その後、機能追加も同じサイクルで進める

## 実験の進め方（ユーザー承認済み）

- **完成の定義**: アプリ本体と、`docs/experience-log.md`（4つの体験を4章立てで記録）の両方が揃ったら完成
- **実験の組み込み方**: アプリは1回だけ作る。「曖昧な依頼 vs 明確な依頼」と「CLAUDE.mdあり vs なし」の比較は使い捨てのブランチで短く試し、結果だけをログに残す。ストリークをわざと不完全に作るループ実験は本線の中で行う
- **担当**: Claudeが実験を実行して記録し、ユーザーは結果を見て感想や判断を加える。プロンプトを書く場面ではユーザー自身にも書いてもらう

## 設計時点での判断（Claudeの判断。変更可）

- **方針ルール**: CLAUDE.mdに書く「方針」は、ユーザーのスキル `coding-guidelines` の3点（冪等性の確保、条件分岐へのコメント付与、ロジック・特にvalidationの共通化）を採用する
- **ストリークの境界ケース**:
  - 今日が未チェックなら昨日までの連続日数を表示する
  - 未来日付のデータは無視する
  - localStorageのデータが壊れている場合は、空の状態から始める
  - 習慣を削除して再登録した場合は新規扱い（履歴は引き継がない）
- **日付の切り替わり**: 画面を開いたまま日付が変わる場合に備え、チェック操作のたびに「今日」を取り直す
- **hook**: Claude Codeのhook（PostToolUse）として `.claude/settings.json` に設定し、編集後にテストを実行する。gitのhookは使わない

## ビルダーに任せること

- ファイル構成と関数の分割
- テストの実行方法（Node.js標準のテストランナーを第一候補とするが、環境に応じて判断してよい）
- UIの見た目（シンプルで読みやすければよい）
- hookの具体的な設定内容
